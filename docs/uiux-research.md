观察日期：2026-09-09。直接查看公开网页、桌面截图及 390×844 移动视口；未登录，未测试原生 App 内的生成过程。以下分开记录观察与设计决策，不把营销描述当作实际完成的体验测试。

| 维度       | Aippy：公开 Web 实测                                                 | Sekai：公开 Web 实测                                       | Hopon 的决策                                                 |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |

## 两条核心路径

1. 发现 → 直接试玩 → 在名称和描述区域上下滑动继续。根据用户提供的实际 App 手势说明及截图，游戏舞台不触发翻页；描述区域的拖动跟随手指，松开吸附。桌面也支持描述区域滚轮、上下按钮和键盘。
2. 创造 → 输入一句游戏描述/使用示例 → 真实生成等待 → 沙箱预览 → 明确点击发布 → 进入公开游戏流。失败保留输入和已有草稿，不自动公开。

## 约束与验收

- 默认首屏即内容，无登录门槛。原创示例始终在社区游戏末尾，并明确标识，不假装是用户生成内容。
- 当前及相邻游戏预加载以保持滑动视觉连续，最多三个 iframe；远离的游戏卸载。当前不保证相邻游戏暂停，示例不播放音频。
- 加载、生成中、生成失败、列表失败、空列表、列表末尾均有明确反馈。
- 生成不显示虚假的百分比；发布必须由草稿拥有者触发。
- 页面不出现评论、点赞、关注、排行榜、积分、付费墙或消息中心。
- 这是从两款产品提取的最小交互方案，并非逐像素复制，也不声称已验证原生 App 的完整体验。
