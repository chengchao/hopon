# 3. The Maker is a Talker in a Durable Object and a Coder whose tools run in a sandbox

## Status

Accepted. Settled by the spikes, prototypes and research linked from the wayfinder map [#111](https://github.com/chengchao/hopon/issues/111), which also holds the decisions still open. The served runtime (`/runtime/v1.js`) and the feed's pause and mute bridge are built in [#137](https://github.com/chengchao/hopon/issues/137). The Talker (one Durable Object per Draft, pi-durable through PiHarness on the `Agent` class) and the Draft routes and WebSocket are built in [#141](https://github.com/chengchao/hopon/issues/141); a Draft's id is the Talker's name, since `Agent` needs a named object. Its `build` tool, which turns the Coder's job into the next Revision in R2, is built in [#143](https://github.com/chengchao/hopon/issues/143), and Publish, which copies a Revision to a Game served from R2, in [#145](https://github.com/chengchao/hopon/issues/145). The Coder in its Container is built in [#139](https://github.com/chengchao/hopon/issues/139): a Container class bound to the API Worker, one instance per Draft, whose `models.internal` handler runs `modelFetch`, with its tools in an E2B sandbox. [#167](https://github.com/chengchao/hopon/issues/167) moves the Coder to a pi-durable Durable Object whose box is a Cloudflare Container, as decided below; until that ships and passes its eval gate, the Coder is still #139's Container with E2B. - `prototype/music-source` (`docs/research/music-source-prototype.md`): a ZzFXM song against a Node synthesizer the model writes, scored blind.
- `prototype/coder-on-workerd` (`docs/research/coder-on-workerd.md`): the Coder on workerd, on pi-coding-agent and on pi-durable, with its box a Durable Object Container.

## Context

Make is one Kimi K2.5 call on Workers AI that returns a whole HTML document. There is no conversation, no way to fix a broken game, and no sound. Before launch, Make becomes a chat with the **Maker**: an agent that makes the game, plays it, fixes it and gives it music and sound. The agent executes code it wrote from a public prompt, so where that code runs is a security boundary, not a convenience.

## Decision

The Creator talks to one Maker. Inside, it is two agents with a narrow contract between them.

- **The Talker holds the conversation.** One Durable Object per Draft in the API Worker. It owns the transcript, the Draft's Revisions and the app's connection, and it decides when to build. It calls the Coder with a structured `build(spec)`, never with the Creator's words. Its loop is pi-durable (`@earendil-works/pi-durable`) run by Cloudflare's `PiHarness` on the Agents SDK's `Agent` class, with exact version pins. pi keeps the transcript and runs in the object's SQLite; its Lifecycle heartbeat restarts the object after an eviction or a deploy and resumes the run from its last checkpoint. `Harness.open` gets `contextRetentionMs: 0` and `documentRetentionMs: 0` so the object hibernates between turns. `build` is registered with `replay: "safe"` and derives its job id from the call, so a resumed turn re-attaches to the running Coder job instead of starting another ([#128](https://github.com/chengchao/hopon/issues/128), `prototype/talker-framework`).
- **Both services are hosted with Effect**, as the API is (ADR 0001): the Talker's and the Coder's Durable Objects. Libraries that aren't Effect (pi, PiHarness, the Container API) are wrapped as Effect services at the edge.
- **The Coder makes the game.** One plain SQLite Durable Object per Draft (`getByName(draftId)`) in the same hopon Worker as the Talker, running pi-durable through PiHarness and `Lifecycle`, the Talker's own stack ([#167](https://github.com/chengchao/hopon/issues/167)). It resumes a job after a crash or an eviction from its last checkpoint, where pi-coding-agent starts over; it needs none of pi-coding-agent's workerd workarounds; it bundles to 777 KB gzipped and starts in about 40 ms. The job id is the submission's `operationId`, so a re-POST re-attaches; the job's ending (music render, files read back) runs in a `GenerationTask` `onYield` hook so it happens with nobody connected; the step limit is a `beforeTool` hook; `playtest` is a tool with `replay: "safe"`. Its tools are pi-durable's `CodingTools` (`read`, `write`, `edit`, `bash`) over an `ExecutionEnv` on the box, with files through `@cloudflare/sandbox`'s `Files`. Skills come through agents' `skills(fromManifest(...))` and its `activate_skill` tool, served from the Worker's memory, and `AGENTS.md` is a prompt section. The model key stays in the Worker's `env` and the Coder calls `modelFetch` per request, so the `models.internal` handler goes. There is no concurrency cap of our own: the account allows 1,500 concurrent vCPU, 750 boxes, and spend is bounded by the per-account quota and the daily global cap ([#34](https://github.com/chengchao/hopon/issues/34)).
  - **The switch is gated on the Coder eval.** The same e2e as [#116](https://github.com/chengchao/hopon/issues/116) (72 builds, the real Talker driving the Coder) on the branch's Worker Preview, through the real Draft API with a Clerk Development user: at least 85% judge pass, a median of at most 62 s and a p95 of at most 120 s, and the owner blind-scores every build the judge fails, as in #116 (89%, 62 s, 112 s). If it falls short, tune `AGENTS.md` for pi-durable's `edit` (an array of `oldText`/`newText` pairs) and paged `read`, and run it again; failing that, the fallback is pi-coding-agent on workerd with its five workarounds, not the `Container` class, which Cloudflare maintains only through 2026-12-31.
  - **Upgrade first.** `agents` 0.28.1 → 0.30 and Pi 1.3 → 1.4 (pi-coding-agent too, so the versions stay together), the docs' minimum for the Pi harness, land in a PR of their own before the Coder changes. The Talker's gate is `talker.yml` (its eviction and snapshot checks, run on every lockfile change), and one `smoke:coder` covers today's Coder.
- **One box per Draft: a Cloudflare Container the Coder starts through `ctx.container`, holding nothing durable and nothing secret, with no egress.** It runs only what the model typed. The Coder starts it with `ctx.container.start({ enableInternet: false, instance: { vcpu: 2, memoryMib: 6144, diskMb: 6000 } })` under `scheduling_policy: "durable_object"`, which has no `max_instances`; the job waits only for `exec()`, and Chromium starts in the background while the model reads the skills and writes the game (`helpers.js` launches it if it isn't up). Between turns the box keeps running for a 5-minute inactivity timeout, set at `start()` and again in the Coder's constructor, since the timeout doesn't survive the object restarting; after that the next turn cold-starts it in about 0.2 s. It is killed at once only when its Draft is deleted, so `MAKER_BOX_IDLE_S` and the Talker's idle alarm go. Its image is `image/build.ts` as a Dockerfile on `node:24-slim` (`node:24` if slim can't run Playwright), with `sandbox-shim` copied from the `cloudflare/sandbox` image at the same version as the `@cloudflare/sandbox` package, built and pushed by `wrangler deploy` (`wrangler preview` for a Preview) in GitHub Actions, since Workers Builds has no Docker. A command runs under `timeout --kill-after=5`, so an abort stops every process it started. The workspace is copied to R2 at the end of every turn and rewritten from the job's `source`, so the box is a cache over R2. E2B is gone: its key, its template build and its team's 20 running boxes.
- **Games are LittleJS, written as `game.ts` against five hooks, run by a served runtime.** `/runtime/v2.js` (v1 until #146 changed the scaffold) is LittleJS core without plugins (about 150 KB, 47 KB gzipped), cached and versioned, plus a scaffold that owns the start screen, score, win and loss, restart, audio unlock and the feed's pause, resume and mute bridge. `GAME_CSP` gains `script-src 'self'` and `media-src 'self'`; the game WebView drops `incognito` so the runtime stays cached. Card, quiz and word games keep the plain-DOM path. A published Game keeps the runtime version it was built with.
- **Playtest before the Creator sees anything.** A script in the box typechecks `game.ts`, runs the game in headless Chromium at 360×540 under the game CSP, and returns console errors and a screenshot the Coder looks at. "Green" is the Coder's and the eval's signal.
- **Models by eval, chosen per agent.** The Talker and the Coder can use different models. Candidates are Claude Haiku 5.5, Claude Sonnet 5.5, DeepSeek and Kimi K3, through the Cloudflare AI Gateway or the provider's own API where the gateway doesn't serve a model; the eval scores quality, cost and time per turn, since a chat can't wait minutes. The spikes measured Haiku 5.5 at $0.004 a game and Sonnet 5.5 at $0.05, both 5 of 5 green, and Kimi K2.5 (today's Make model) at about eight minutes a game, which rules out K2.5 itself.
- **Sound.** Sound effects and short stingers are ZzFX, synthesized in the runtime. Music is optional per game, and the Coder writes it as code: `music.mjs`, a synthesizer with its own oscillators, envelopes, drums and mix that imports only `node:` built-ins, written from the Talker's genre and mood brief. It runs in the box and renders `music.wav`, which the harness re-encodes to Opus at 64 kbps and wraps, base64, in `music.js`. A follow-up patches the script and renders again. The music ships as a script, not as `music.opus`, because `GAME_CSP` keeps `connect-src 'none'` (ADR 0002) and a gapless loop needs Web Audio, which needs the bytes in the page; `music.js` is served compressed, so the base64 costs little on the wire. There is no `audio.json` ([#146](https://github.com/chengchao/hopon/issues/146)). Nothing in the box calls a provider ([#129](https://github.com/chengchao/hopon/issues/129)).
- **The app talks only to the Worker.** pi commits every change of a turn to storage before anything is shown, whether or not anyone is connected. The app connects over a WebSocket (a one-time ticket fetched with its Clerk token) and, on every connect, gets pi's snapshot of the session, then live batches. There is no replay cursor; a reconnect is a fresh snapshot, about 3.5 KB per build turn. While pi is busy the Talker sends at least one message every 15 s, and the app treats 40 s of silence as a lost connection. A turn always ends with `turn_done` or `turn_failed`, taken from pi's submission records; the Talker aborts a turn whose Coder never answers after 150 s, or 180 s with music, and the Coder gives up first, at 120 s or 150 s. Messages and Stop are POSTs through the Worker, which keeps Screening, moderation, publish and the secrets.

## Considered

- **One agent: pi on a Node server, the design before this one.** Simpler, one prompt to tune. Splitting gives the conversation a home that is free while idle and always responsive, lets the Coder be a restartable job runner that never reads the Creator's words, and lets each half use a different model.
- **An Effect AI loop of our own** for the Talker (`effect/ai` `LanguageModel` and `Toolkit`, a numbered event log replayed by `since=N`). It survived a restart mid-build and re-attached to the job too, was half the bundle and stayed in the API's style, but it is more code of ours (337 lines against 157) on an ecosystem too small to lean on; Cloudflare and pi own the run instead.
- **Vercel AI SDK** for the Talker. Runs in a Durable Object with only `nodejs_compat`, but it is another loop of our own.
- **Claude Agent SDK in the sandbox.** The best-tuned harness, but it must run where the shell is, so a key and the transcript sit in the box, and it is Claude-shaped. Kept as a reference for skills and evals.
- **pi inside the sandbox.** The same key-in-box and state-in-box costs, plus a runner per box. pi's `operations` make it unnecessary.
- **Our own loop with one `run_node` tool** instead of pi's tools. Spike A built it: 3 turns a game by construction and slightly cheaper.
- **E2B for the box, the design before #167.** A real VM, paused between turns at no cost with Chromium warm (resume 0.2 s, playtests 1.5–2 s faster). But it needed the Coder in a Container of its own to hold its key, a second vendor and template build, and its team's 20 running boxes became our concurrency cap, which idle Drafts filled after a rollout.
- **pi-coding-agent on workerd** for the Coder. It ran unchanged in a Durable Object, but needs five workarounds (`define`s for `import.meta`, TypeBox's interpreted checker, no image resizing, drained streams, a per-job `fetch` patch through `AsyncLocalStorage`), starts over after a crash, and is four times the bundle. It is the fallback if pi-durable fails the eval.
- **pi in a container of its own, with the box in a separate Durable Object.** The spike's fallback; not needed once pi ran on workerd.
- **A Coder Worker of its own**, bound by `script_name`. It kept pi-coding-agent's `define`s and startup out of the Talker's; pi-durable has neither, and one Worker keeps one deploy, one Preview and one set of versions. Split it if the two share isolates' 128 MB badly.
- **Container snapshots between turns.** They save the disk only, not Chromium, and restore slower (1.4–1.6 s) than a cold start; the box is rebuilt from the job's `source` anyway.
- **A running-builds counter of our own** in place of `max_instances`. It would shape bursts that 750 boxes absorb; the daily cap bounds spend.
- **Hand-made file operations over `exec()`** (`cat`, `stat` parsed from text). No shim in the image, but untyped errors guessed from stderr.
- **A fake in-memory box for plain `wrangler dev`.** It can't run Chromium, so it can't playtest, and would mostly test itself.
- **Docker on a server we run** instead of a managed box (E2B, Cloudflare Containers). Cheaper at volume, but a container is not a VM boundary for code from a public prompt without gVisor or Kata, and pause, egress policy and capacity become ours.
- **Fly, Fargate, Cloud Run** for the Coder. All work; each adds a public endpoint, a shared secret and a second deploy. App Runner and Lambda can't hold a 5-minute turn.
- **SSE** for events. It works on iOS through `expo/fetch`, but Cloudflare recommends WebSockets with hibernation for Durable Objects, React Native has `WebSocket` built in, and an open SSE stream bills the object's duration.
- **A ZzFXM song the runtime plays.** Tiny and needs no render step, but it scored lower in a blind listen (3.5 against 3.9), its player cuts ringing notes at the loop end, leaving dips or up to 0.65 s of silence, and it renders on the main thread at the first tap.
- **Google Lyria 3 Clip** ($0.04 per 30 s clip). Not heard: the key on hand was free tier, which allows no requests. It would put a provider call behind the box, and a follow-up could only regenerate the clip, not edit it.
- **ElevenLabs Music.** Good output, but its self-serve plans are for individual use only, and its rights when bought through Cloudflare's gateway are unstated. MiniMax trains on input and output.
- **A curated CC0 music library**, as the source or as a fallback. Fourteen loops were found; too few to give games their own sound, and keeping one as a fallback is more code than an optional track.
- **Phaser or Kaplay.** Larger APIs the model knows better, but they expect loaded assets, own the loop, and can't be linted against an allowlist. All four models wrote working LittleJS from a one-file skill.

## Consequences

- One more thing to deploy: the box's image, built and pushed by the same GitHub Actions deploy as the API ([#37](https://github.com/chengchao/hopon/issues/37)). An image may be no larger than the box's disk, and the account stores 50 GB of images; every Preview has its own container app, so at about 2 GB an image, old Previews' apps get pruned when the store fills.
- The box's isolation is Cloudflare's: its runtime restores a virtual machine per Container, and under the `durable_object` policy `exec`'s `user` restricts nothing. Our own boundary is that the box holds no secrets, has no internet and keeps nothing durable.
- Local dev: `pnpm -F worker dev:coder` runs the Talker, the Coder and the box in one `wrangler dev` with Docker. Plain `dev` and the tests have no box, so a build there fails with a clear error. `smoke:coder` stays the end-to-end check.
- Cost per game moves from cents of Workers AI to about $0.01 to $0.06 of model tokens, about $0.003 of box time (2 vCPU / 6 GiB for a 60 s build) plus $0.0009 a minute while it waits out its 5 minutes for the next turn, and about $0.005 more for music on Haiku 5.5 ($0.03 on Sonnet 5.5). Music adds 18–63 s to the turn that writes it. A global cap ([#34](https://github.com/chengchao/hopon/issues/34)) matters more; per-account quotas stay as they are for now.
- The AI disclosure ([#52](https://github.com/chengchao/hopon/issues/52)) names every model provider the eval picks. Draft snapshots join the prune job ([#39](https://github.com/chengchao/hopon/issues/39)).
- Unpublished Drafts need assets the WebView can load without a Clerk token, since subresources carry no headers.
- Playtests run about 1.5–2 s slower than on E2B, unexplained and not CPU (4 vCPU didn't help); inside the 120 s deadline.
- PiHarness is beta and pi-durable is experimental, and now both agents run on them. Pin exact versions, and run the prototype's eviction and snapshot scripts (`talker.yml`) and `smoke:coder` as the test for every upgrade. The Talker's bundle is about 965 KiB gzipped and the Coder's about 777 KB; split them into two Workers if that matters. The Coder's isolate memory (base64 screenshots, `music.js` up to 438 KB) is unmeasured. Cloudflare serves Claude Haiku 5.5 from its own catalog (REST `/ai/v1/messages`), not through the AI Gateway's Anthropic route, so `modelFetch` rewrites pi's Anthropic requests into the catalog's narrower format.
- Still to check on a real iPhone: the ringer switch, reconnecting after iOS suspends the app, the served runtime under WebKit's `sandbox allow-scripts`, and that the Opus music loops without a gap however the feed plays it (the prototype used Web Audio).

## Revisit when

- the eval shows a cheaper model matching Sonnet's quality through our own loop but not through pi's tools, or
- a PiHarness or pi-durable upgrade breaks resume after eviction, or snapshots grow too large to resend on every reconnect, or
- idle boxes cost more than cold starts save, or Cloudflare's Container pricing, limits or isolation change, or
- Coders sharing isolates run short of memory, or
- model-written music stops sounding good enough next to a generated source whose terms allow it.
